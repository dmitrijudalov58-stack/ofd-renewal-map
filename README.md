# Карта продлений ОФД

BI-инструмент для карты продлений ОФД: загружаешь XLSX-выгрузку — весь разбор и расчёт метрик идёт прямо в браузере, файл никуда не отправляется. Библиотека из 25 готовых виджетов (клиенты, кассы, партнёры, коды ОФД), перетаскиваются на рабочую область по drag-and-drop, экспорт любой таблицы в CSV.

## Запуск

Статический сайт, сборки не требует. Варианты:

- **Локально**: открыть `index.html` напрямую в браузере.
- **GitHub Pages**: включить Pages на ветке `main` в настройках репозитория — сайт откроется по ссылке `https://<логин>.github.io/<репо>/`.

## Структура

```
index.html            разметка + подключение скриптов
css/styles.css         дизайн-токены и стили
js/parser.js            XLSX (3 листа) -> нормализованные строки
js/metrics.js           вся бизнес-логика: клиенты/кассы/отток/резерв/каналы
js/widgets.js            рендер 25 виджетов поверх metrics.js
js/dnd.js                перетаскивание из библиотеки на холст
js/export.js             экспорт таблицы в CSV
js/app.js                загрузка файла, период, as-of, склейка всего
js/vendor/xlsx.full.min.js  SheetJS — грузится лениво, только при выборе файла
```

## Логика (кратко)

- **Клиент** = ИНН организации (или ИНН физлица, если организации нет).
- **Касса** = РНМ ККТ. **Код ОФД** = PIN, техническая единица.
- **As-of дата** фиксируется в момент загрузки файла — не «плывёт» при повторном открытии сайта.
- **Период** — произвольный диапазон дат, фильтрует только потоковые виджеты (метка «период»); снэпшот-виджеты (метка «as-of») его игнорируют.
- **Отток кассы** = «Общая дата окончания» попала в период. **Отток клиента** = отток всех его касс.
- **Реанимация** = была в оттоке на конец периода, вернулась в течение +3 месяцев.
- **Продления кассы** = число зарегистрированных кодов в цепочке минус 1 (отозванные исключены, флаг «Первичная» не используется как источник истины).
- **Каналы партнёров**: Ольга Зибер — по подстроке в поле «Партнёр» (ЛК ОФД / ОПС ЭДО / ОППС ЭДО); Лариса Пенигина — по списку значений поля «Центр продаж»; всё остальное — «Партнёры».

Полная спека с формулами по каждому виджету — отдельный документ, см. историю разработки.

## Тесты (для разработки, не для сайта)

Требуют реальную XLSX-выгрузку локально (не входит в репозиторий — реальные данные клиентов):

```bash
npm install
OFD_TEST_FILE="/путь/к/выгрузке.xlsx" npm test
```

`test/smoke.js` — проверяет ядро расчётов (parser.js + metrics.js) в Node.
`test/browser-smoke.js` — прогоняет все 25 виджетов и ключевые взаимодействия (фильтр риска, сортировка, раскрытие по клику, экспорт) в jsdom, максимально близко к реальному браузеру.

## Приватность

Все данные (ФИО, телефоны, email, ИНН) обрабатываются только в браузере пользователя. Ничего не отправляется на сервер — сайт статический, без backend и без аналитики. Реальные XLSX-выгрузки исключены из репозитория через `.gitignore`.
