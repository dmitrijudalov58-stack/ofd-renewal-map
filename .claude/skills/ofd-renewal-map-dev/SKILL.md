# Карта продлений ОФД — контекст разработки

Сайт: https://dmitrijudalov58-stack.github.io/ofd-renewal-map/
Репо: https://github.com/dmitrijudalov58-stack/ofd-renewal-map
GitHub-аккаунт для push: `dmitrijudalov58-stack`, `gh` уже авторизован на машине Димы.

## Что это и как устроено

Статический BI-инструмент для карты продлений ОФД. Zero build step — просто `<script src>` теги, без npm-бандлера в продакшене (npm нужен только для dev-тестов, см. ниже). Загружаешь XLSX-выгрузку → весь разбор и расчёт метрик идёт в браузере, ничего никуда не отправляется.

```
index.html            разметка + подключение скриптов по порядку
css/styles.css         дизайн-токены (ledger-стиль: сажево-тёмно-бирюзовый, Georgia для заголовков)
js/parser.js            XLSX (3 листа) -> нормализованные строки, читает колонки ПО ПОЗИЦИИ (не по имени —
                         в файле задвоен заголовок "Партнер": имя партнёра на позиции 19, денежная сумма на 25)
js/metrics.js            вся бизнес-логика: buildModel + все computeX функции
js/widgets.js            рендер 25 виджетов поверх metrics.js, реестр WIDGETS{}
js/dnd.js                drag-and-drop из библиотеки на холст, экспорт-кнопка
js/export.js             CSV-экспорт (с BOM для кириллицы в Excel)
js/app.js                загрузка файла, период/as-of, склейка
js/vendor/xlsx.full.min.js  SheetJS, грузится лениво при выборе файла
test/smoke.js             Node-тест ядра метрик на реальном файле
test/browser-smoke.js     jsdom-тест всех 25 виджетов + интерактива (максимально близко к браузеру)
```

## Ключевая модель данных

- **Клиент = ИНН** (организации; ИНН физлица, если организации нет — 892/551 таких строк, статус Новый/Выдан, дата появления = "Дата создания", не "Дата активации")
- **Касса = РНМ ККТ**
- **Код ОФД = PIN** — техническая единица, три статуса: Новый/Выдан (резерв партнёра, без клиента) / Зарегистрировано (клиент активировал) / Отозвано (аннулирован, нигде больше не участвует)
- Строка выгрузки = код (PIN), НЕ клиент и НЕ касса — на этом завязана вся логика buildModel в metrics.js

### Формулы, которые нельзя менять не подумав (согласованы с Димой пошагово)

- **Отток кассы** = «Общая дата окончания» попадает в [начало периода; конец периода] (важно — с НИЖНЕЙ границей, иначе считает накопительный отток за всё время)
- **Отток клиента** = отток АБСОЛЮТНО ВСЕХ его касс (последняя истекла в периоде)
- **Реанимация** = была в оттоке на конец периода (см. `kassaLapsedAt`/`clientLapsedAt` — используют per-code individual end date с фолбэком created+тариф, НЕ "Общая дата окончания", т.к. та отражает только финальное состояние) + новая активация в (конец периода; конец периода+3 мес]
- **Продления кассы** = COUNT(коды со статусом "Зарегистрировано" в цепочке) − 1. НЕ полагаться на флаг "Тип активации" (в 298 из 263 675 цепочек встречается два "Первичная" подряд — флаг иногда врёт)
- **Воронка (B4)**: Активировано = статус "Зарегистрировано" (эквивалент "есть ИНН клиента", взяли через статус, а не через сырое наличие ИНН — иначе отозванные-но-когда-то-активированные коды задваивались бы в "Активировано" И "Отозвано", и три столбца не сходились бы в "Создано")
- **Каналы партнёров**: Оля Зибер = поле "Партнёр" содержит "ЛК ОФД"/"ОПС ЭДО"/"ОППС ЭДО"; Лариса Пенигина = поле "Центр продаж" — один из 11 зафиксированных значений (список в `metrics.js` → `LARISA_CENTERS`); всё остальное = "Партнёры"
- **Топ партнёров по объёму (b3-top)**: изначально было "новые клиенты/кассы/продления ЗА ПЕРИОД", по фидбэку Димы упростили до общих клиентов/касс на as-of — чип у виджета соответственно "as-of", не "период"

### Чип as-of / период — держать честным

Каждый виджет размечен `scope: "as-of" | "период"` в реестре `WIDGETS`. as-of = снэпшот на дату загрузки файла, верхний фильтр периода не действует. период = фильтруется диапазоном дат. **Если меняешь логику виджета так, что она перестаёт зависеть от периода (или наоборот) — обязательно поменяй chip и в `js/widgets.js`, и в библиотеке `index.html` (`.lib-item .lchip`)**. Уже была ситуация, когда я забыл это сделать при рефакторинге b3-top — поймали на ревью.

## Общие компоненты (трогаешь один — проверяй всех потребителей)

- **`kassaDetailTable(kassaArray, asOf, opts)`** (widgets.js) — таблица касс с фастфильтрами (партнёр/тариф/статус/ИНН/мин.продлений) + экспорт. Используется в b2-renewals, b2-renewdist, b2-tariff. Правишь колонки/фильтры — проверь все три.
- **`barList(rows, opts)`** — SVG horizontal bar chart (НЕ div-прогресс-бары — та версия была нечитаема, пастельная заливка на сером фоне; переписана на контрастную палитру #3987e5→#104281 по фидбэку). Используется в b1-kassdist, b1-age, b2-renewdist, b2-tariff (overview-часть), b3-channels.
- **`lineChart(months, series, opts)`** — линия+область, hover-подсказка на КАЖДОЙ точке (не только последней), `series[i].tooltips[j]` для кастомного текста подсказки. Используется в b1-new, b1-churn, b1-netgrowth.
- **`makeSortableTable(headers, rows, opts)`** — сортировка по клику: `dir[col]=true` после первого клика ВСЕГДА означает "по возрастанию", независимо от того как строки были отсортированы до клика (иначе клик по уже-отсортированной колонке визуально ничего не менял). `headers[i].html=true` — колонка НЕ экранируется (для status-pill и т.п.), остальные колонки экранируются через `esc()` автоматически.

## Найденные баги — не откатить их случайно

1. **Пробелы в названиях партнёров ломали группировки.** У части строк в поле "Партнёр" (и др. текстовых полях) — лишний пробел по краям, из-за чего "ООО Х" и " ООО Х" считались разными сущностями везде (фильтры, топы, каналы). Фикс — `cleanStr()` в `parser.js`, обрезает пробелы у всех текстовых полей при нормализации строки. Если увеличивается число "уникальных" партнёров после апдейта файла — сначала проверь этот угол.
2. **HTML не экранировался** — названия партнёров/организаций вставлялись в `<option>`/`<td>` напрямую. Фикс — `esc()` в widgets.js, применяется в `makeSortableTable` (кроме колонок с `html:true`) и во всех местах, где строим `<option>`.
3. **jsdom quirk, не баг реального браузера**: `node.querySelector(".widget-body > *")` иногда возвращает `null` в jsdom (nwsapi), хотя `.firstElementChild` на том же узле работает исправно. В `dnd.js` и тестах используется `.querySelector(".widget-body").firstElementChild` — не возвращай `> *` обратно, даже если кажется эквивалентным.
4. **Cross-realm `instanceof Date`** — если в тесте парсишь XLSX через Node-модуль `xlsx`, а `parser.js`/`metrics.js` выполняются в jsdom-window (другой realm) — `instanceof Date` между ними ломается и даёт тихие нули везде, где есть даты. В `test/browser-smoke.js` xlsx грузится через `win.eval()` в ТОТ ЖЕ jsdom-realm — так и должно быть, не откатывай на `require("xlsx")` для парсинга внутри jsdom-теста.
5. **`git push` 403 с чужим аккаунтом** — на машине был закэширован в osxkeychain credential от другого GitHub-аккаунта. Фикс — `gh auth setup-git`, прописывает per-host `credential.https://github.com.helper` override, который бьёт global `osxkeychain`.

## Тестирование

```bash
npm install   # jsdom, xlsx — только dev-зависимости, в продакшен сайт не попадают
OFD_TEST_FILE="/путь/к/реальной/выгрузке.xlsx" npm test
```

- `test/smoke.js` — ядро (parser+metrics) в чистом Node, печатает все ключевые агрегаты для визуальной сверки
- `test/browser-smoke.js` — прогоняет все 25 виджетов + интерактив (фильтры, drill-down в B4, сортировка, экспорт, rerenderAll при смене периода) в jsdom
- Тестовый файл **не в репозитории** (реальные ФИО/телефоны/ИНН клиентов), путь передаётся через `OFD_TEST_FILE`
- Известные референсные числа на файле `...ОФД Подключение 01.01.2020-30.07.2026.xlsx`, as-of 2026-07-30: activeClients=92983, clientsAtRisk(30d)=10707 — если видишь другие числа на этом же файле, разбираться, не игнорировать

## Деплой

- GitHub Pages: `build_type=legacy` (branch-based деплой, БЕЗ workflow — сайт статический, сборка не нужна). Не переключай на `workflow`, иначе понадобится `.github/workflows/*.yml`
- После `git push` в `main` пересборка Pages запускается автоматически; форсировать вручную: `gh api -X POST repos/dmitrijudalov58-stack/ofd-renewal-map/pages/builds`
- Проверка статуса: `gh api repos/dmitrijudalov58-stack/ofd-renewal-map/pages/builds/latest --jq .status` (`building` → `built`)
- `.gitignore` блокирует `*.xlsx`/`*.xls` — защита от случайного коммита реальной выгрузки

## Рабочий процесс правок (порядок, который использовался всю сессию)

1. Правишь `metrics.js` → сразу гоняешь `node test/smoke.js` с реальным файлом, смотришь на числа глазами
2. Правишь `widgets.js`/UI → `node test/browser-smoke.js` (полный прогон, ловит runtime-ошибки и регрессии интерактива)
3. Только после зелёного smoke — `git add` конкретных файлов (никогда `-A` не глядя, проверять что не затянуло xlsx), commit, push
4. После push — дождаться `built` в Pages API, проверить фикс на живом URL curl'ом (не считать готовым по одному пушу)

## PDF-версия памятки (для рассылки без аккаунта Claude)

На машине Димы нет ни Chrome, ни wkhtmltopdf — печать HTML→PDF через headless Chromium из пакета `puppeteer` (npm), не через скилл `make-pdf` (тот рассчитан на markdown-вход и тянет инфраструктуру gstack, которая тут не нужна).

```bash
mkdir -p /tmp/pdfgen && cd /tmp/pdfgen && npm init -y >/dev/null 2>&1 && npm install puppeteer

node -e '
const puppeteer = require("puppeteer");
(async () => {
  const browser = await puppeteer.launch();
  const page = await browser.newPage();
  await page.goto("file://" + "/Users/dmitrij/Desktop/Агенты/ofd-renewal-map/docs/guide.html", { waitUntil: "networkidle0" });
  await page.emulateMediaType("screen");
  await page.pdf({
    path: process.env.HOME + "/Downloads/Карта продлений ОФД — памятка.pdf",
    format: "A4", printBackground: true,
    margin: { top: "14mm", bottom: "16mm", left: "12mm", right: "12mm" },
  });
  await browser.close();
})();
'
```

Результат уже лежит в `~/Downloads/Карта продлений ОФД — памятка.pdf` (8 страниц, кириллица проверена через `pdftotext`). Перегенерировать этим же рецептом после любой правки `docs/guide.html`.
