# Выпуск Карты продлений ОФД без рассинхрона

Источник сайта — **корень Git-репозитория**, не каталог `cloudflare/public/`. Скрипт `cloudflare/deploy.sh` удаляет прежний `public/`, копирует туда свежие `index.html`, `css/`, `js/`, `docs/`, PWA-файлы и запускает Wrangler. `git push` **не обновляет** сайт, а деплой **не отправляет** изменения в Git.

Боевой адрес: https://ofd-gate.dmitrijudalov58.workers.dev/ . Worker: `ofd-gate`. GitHub Pages выключен и включать его нельзя. Basic Auth и админка доступа этим процессом не меняются.

## Перед выпуском

1. Убедитесь, что работаете в **той копии**, которую собираетесь выпустить: `pwd`, `git branch --show-current`, `git status --short`, `git rev-parse HEAD`, `git remote -v`. При грязной основной папке заведите отдельный worktree; не делайте `git reset --hard`, `git clean -fd` и не используйте общий `git stash` для освобождения основной папки.
2. Посмотрите **все** изменения: `git diff --check`, `git diff --stat`, `git diff -- <каждый планируемый файл>`, а также незакреплённые файлы через `git status --short`. В коммит добавляйте **только явно проверенные пути**, без слепого `git add -A`. Не включайте клиентские XLSX/пароли, B3 или чужие незаконченные правки.
3. Запустите актуальные тесты. Для большой выгрузки Node может потребовать память: `NODE_OPTIONS='--max-old-space-size=6144' OFD_TEST_FILE='/путь/к/выгрузке-ОФД.xlsx' OFD_1C_TEST_FILE='/путь/к/сверке-1С.xlsx' npm test`. Если одного источника нет, укажите это в отчёте. Проверьте интерфейс локально в настоящем браузере и откройте сгенерированный Excel в табличном приложении.
4. Проверьте Cloudflare-аккаунт командой Wrangler `whoami` и убедитесь, что это аккаунт, которому принадлежит `ofd-gate` (в проекте — `dmitrijudalov58`, ID `77ea408fe29e178a8c948b352edb830e`). Не переносите токены и пароль в чат или репозиторий. При `Authentication error 10000` **не** повторяйте деплой наугад: сначала смените активный аккаунт Wrangler на нужный.

## Commit → push → deploy

В рабочем worktree:

1. `git fetch origin`; сравните `git rev-parse HEAD origin/main`. При расхождении сначала согласуйте безопасное включение чужих коммитов и повторите тесты. Не форсируйте push.
2. `git add -- <проверенные пути>`; `git diff --cached --check`; `git diff --cached --stat`; проверьте содержание staged diff и создайте commit с понятным сообщением.
3. Для боевого выпуска доведите `origin/main` до проверенного коммита **без force-push** (через merge/fast-forward или PR). Push только feature-ветки не синхронизирует основной репозиторий с сайтом. Сверьте `git rev-parse HEAD` и `git ls-remote origin refs/heads/main`: они должны указывать на тот же SHA. `git status --short` не должен содержать незакоммиченных файлов, участвующих в сборке.
4. Из **того же worktree и того же SHA** выполните `cd cloudflare && ./deploy.sh`. Скрипт должен вывести успешный Wrangler deployment и версию Worker. Если Wrangler отсутствует, установите/предоставьте проверенную локальную версию; не полагайтесь на скачивание неизвестной версии во время выпуска.
5. Проверьте содержимое собранного `cloudflare/public/` и живой URL. Без авторизации сайт обязан вернуть 401. В уже авторизованной пользовательской сессии выполните полный сценарий: загрузка ОФД и 1С, ввод параметра, пересчёт, скачивание книги и проверка скачанного файла. Проверьте версию Worker и отсутствие ошибок браузера. **401 без входа доказывает только наличие защиты, не работу раздела.** Не отправляйте пароль исполнителю в сообщении.

После проверки запишите: исходный SHA, URL, Worker version, результаты тестов и боевой проверки, перечень непроверенного. Статус «готово» допустим только после проверки там, где пользователь работает.

## Если сайт уже обновили до коммита

Не пытайтесь «синхронизировать» сайт простым push: опубликованное содержимое не обязано совпасть с текущей папкой. Сначала снимите SHA и полный diff грязной папки; определите, какие именно файлы были скопированы `deploy.sh`, и перенесите их в изолированный worktree вместе с тестами. Зафиксируйте **тот же проверенный состав**, сделайте push, потом **повторите деплой именно из зафиксированного SHA**. Лишь после этого сравнивайте боевой сценарий с исходниками. Если состав предыдущего деплоя неизвестен, честно укажите это; не выдавайте новый commit за доказательство истории предыдущей публикации.

## Если выпуск прервался

- Commit есть, push нет: сайт не обновился; проверьте remote и повторите push после сверки.
- Push есть, deploy нет: GitHub новее сайта; повторите deploy из нужного чистого коммита.
- Deploy есть, проверка под логином нет: сайт опубликован, но работа пользователя **не проверена**. Нужна уже авторизованная браузерная сессия владельца либо помощь владельца при проверке; не подменяйте её локальным стендом.
- В браузере старый код: проверьте `version.json`, сетевые ответы, кеш и версию Worker; `cloudflare/public/` пересобирается, редактировать его вручную нельзя.
