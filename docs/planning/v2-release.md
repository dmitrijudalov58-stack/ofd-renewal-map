# Планирование 2.0 — встроенный раздел 06.11.2026

Обновление: в сводном борде под карточками добавлены ручной апсейл ОФД (изначально 5%), загрузка и снятие списка касс без чеков, сравнение исходного прогноза с прогнозом после исключений. Апсейл применяется к сумме продлений ОФД пропорционально доле оставшихся касс к продлению с тарифом менее 36 месяцев. Обмен с 1С остаётся отдельным расчётом. При неизвестном тарифе и ненулевом апсейле итог клиента остаётся незаполненным.

Основная выгрузка содержит РНМ, а список без чеков — заводской номер; они не приравниваются. Пользователем согласовано исключение только при единственном совпадении ИНН + календарного дня окончания + срока тарифа в обеих выборках. Повторы не задваивают исключение; конфликтующие номера и неоднозначные группы не исключаются. Совпадения вне планового года не меняют план.

При частичном исключении ИНН сохраняется с одним средним чеком, прежней когортой и вероятностью. Первое окончание, канал и доля апсейла определяются по оставшимся кассам. Если все кассы к продлению исключены, ИНН удаляется только из плана ОФД. Историческое ретро и продления 1С не меняются. Список хранится только в памяти браузера; после перезагрузки его нужно загрузить заново. Процент апсейла сохраняется в настройках новой модели.

В Excel добавлены базовая сумма, доля и прибавка апсейла, сравнение сценариев на момент выгрузки и полный протокол всех входных строк. Формулы клиентских строк и итогов учитывают апсейл. Тесты покрывают смешанные тарифы, пустые и нулевые чеки, частичные и полные исключения, повторы, конфликты, будущие покупки, снятие фильтра, синхронизацию бордов и экспорт. Полный реальный список проверен локально; частные исходники и показатели не публикуются.

Раздел «Планирование 2.0» находится в общей библиотеке бордов основной страницы `/`. Пять бордов добавляются на общий холст обычным перетаскиванием: параметры, средние чеки и сводный план; когорты и вероятности; каналы и когорты; месяцы; клиенты по ИНН. Загрузка исходных файлов — общими кнопками ОФД и Обмена с 1С в верхней панели. Отдельная ссылка внизу меню удалена. Прежнее планирование сохранено. Настройки новой модели изолированы, изменения сразу синхронизируются между её бордами. Общий кэш позволяет считать один план для всех бордов. Сохраняется стандартная раскладка холста.

Новая модель получает исходные строки из тех же загруженных файлов до дедупликации старой модели. Для неё Excel читается с сырыми числовыми датами, без преобразования cellDates: так сохраняются календарные дни исходного файла независимо от часового пояса браузера. Старый загрузчик сохраняет свою обработку; чтение файлов для новой модели увеличивает время общей загрузки. Это сохраняет согласованные правила истории и точных дублей; прежняя обработка данных других разделов не меняется. Ошибки формата для нового расчёта показываются в борде параметров.

Исходная база выпуска — `dc7c3e5f9c39e03b83f08652d58d5a69f9262be9`, совпавшая с текущим GitHub HEAD перед работой. Действовавшая на тот момент версия Worker — `0b3719ff-31d3-49bb-b871-7081e3d1a51a` от 03.11.2026. Исходные грязные worktree не перезаписывались; подготовка идёт в отдельной папке Downloads/ofd-planning-release.

Правила: восемь когорт ОФД; 1С по ИНН без когорт; отдельные средние чеки на продлившегося клиента по каналам продуктов; сумма = вероятность × чек клиента; месяц — первое окончание покрытия; канал ОФД по этой покупке, канал 1С по партнёру ИНН в ОФД. Неоднозначный канал уточняется вручную. Пустой чек не превращается в ноль; ручная вероятность требует причины. Ретро по умолчанию — 2025. Срез — начало выбранного дня.

Состав и правила загрузки перенесены из локальной проверенной версии `Downloads/ofd-planning-v2`. В браузере выполнена сверка реальных файлов ОФД и 1С, совпали контрольные значения и все восемь когорт. Проверена полная совместная выгрузка продуктов. Клиентские данные, бизнес-показатели реальной сверки, исходные XLSX и приватные контрольные фикстуры не включаются в репозиторий и не отправляются серверу. Воспроизводимая сверка с частным эталоном допускается через `P2_REFERENCE_FILE`.
